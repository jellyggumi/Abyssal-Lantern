# 궤적 프리뷰가 무엇에 막히는가 — 전수 계산 (정정판)

- date: 2026-08-14
- 발단: 사용자 보고 *"포물선쪽이 적쪽으로 갈수없는 위치로 표시되고 있어. 앞에 장애물로
  포커싱되어서 포물선이 이상하게 표현돼."*

> **이 문서는 한 번 틀렸고 두 곳을 고쳤다.** 초판이 (1) `MaxSpeed`를 **25.2**로 썼는데
> 실제는 **17.5**이고(`LaunchPowerCurve.cs:48`, 작업 #60이 내렸다), (2) 착지 판정이
> 상승 구간을 건너뛰지 않아 **발사점 자신을 착지로 반환**했다. PM 레인이 (1)을 반박했고
> (2)는 그 반박을 검증하다 드러났다. 아래는 정정 후 값이며, 적분기가 해석해와
> **0.1% 이내로 일치**하는 것을 먼저 확인했다(45°·전속 31.18u 대 31.22u).

- 방법: 런타임과 같은 적분식 — 반암시적 오일러 `dt=0.02`, 400스텝, 천장 y=20
- 대상: 각도 10~80°(5°) × 당김 10~100%(5%p) = **285 조합**, 당김 커브 `speed = 17.5·√draw`
- 기하: 진지 x=−17, 자기 성채 x=−7..−4, 적 성채 x=+4..+7, 적 코어 x=7.85~10.15,
  필드 솔리드는 내부 레인 `{−2.5, 0, +2.5}`

---

## 1. 무엇이 궤적을 멈추는가

| 궤적이 처음 만나는 것 | 조합 | 비율 |
|---|---:|---:|
| **적 성채 (의도된 결과)** | 18 | **6.3%** |
| **자기 성벽** | 116 | **40.7%** |
| 지면 (미달) | 114 | 40.0% |
| Patrol (y=3.7~4.7 솔리드) | 27 | 9.5% |
| MiniTower (y=0~2 솔리드) | 10 | 3.5% |

**사용자가 본 "앞의 장애물"은 40.7%에서 자기 성벽이다.** 필드 장애물은 13.0%.

## 2. 프리뷰는 사실을 말하고 있다

궤적은 첫 비트리거 콜라이더에서 멈추고(`LaunchManager.cs:1034-1052`) **같은 팀 유닛만**
무시한다(`:1008`). 자기 성벽은 무시 대상이 아니고 **그것이 옳다** — 실제 발사체도 막힌다.
B1이 플레이어 자기 턴의 **71%(10/14)에서 자기 성벽 블록 파괴**를 실측했다.

**렌더러 결함이 아니다. 프리뷰가 정확한데 읽히지 않았다.**

## 3. 진짜 결함 — 기본 조준이 자기 성벽에 떨어진다

키보드/Space 경로는 당김 커브를 **타지 않는다**. `OneShotSiegeRules.Velocity`(`:57-61`)가
**선형 `Lerp(minSpeed, maxSpeed, power)`** 를 쓴다:

```
aimPower = 0.55  (LaunchManager.cs:62)
speed    = Lerp(3, 17.5, 0.55) = 10.975 m/s
45°에서 착지 x = −4.42 ~ −5.82   ← 자기 성채가 x=−7..−4
```

**기본 조준으로 쏘면 자기 성벽에 맞는다.** 적 성채(x≥4)까지 **8.74u 부족**하다.

45°에서 `aimPower`별 착지점:

| aimPower | 속도 | 착지 x | 판정 |
|---:|---:|---:|---|
| 0.48 | 9.96 | −7.00 | 자기 성채 |
| 0.52 | 10.54 | −5.82 | 자기 성채 |
| **0.55 (출하 기본값)** | **10.975** | **−4.7** | **자기 성채** |
| 0.56 | 11.12 | −4.42 | 자기 성채 |
| 0.68 | 12.86 | −0.27 | 중립지 |
| **0.80** | **14.60** | **4.68** | **적 성채 (최소 도달)** |
| 0.84 | 15.18 | 6.40 | 적 성채 |
| 0.88 | 15.76 | 8.19 | 적 코어대 |
| 1.00 | 17.50 | 14.18 | 지나침 |

**기본값 0.55에서 도달 최소값 0.80까지 0.25이고, `powerStep = 0.04`이므로 키 입력 6.2회다.**
즉 조준을 배우지 않은 플레이어의 도달률은 6.3%가 아니라 **0%** 다.

원인은 작업 #60이 `MaxSpeed`를 25.2 → 17.5로 내릴 때 **`aimPower = 0.55`를 함께 조정하지
않은 것**이다. 구 속도에서 0.55는 도달했다.

## 4. 부수 결함 — 화면에 표시되는 파워가 모델과 다른 매핑이다

HUD는 **당김 커브** 기준으로 파워를 표시한다(`LaunchManager.cs:1078`
`DrawForSpeed(velocity.magnitude, maxLaunchVelocity)`). 그런데 키보드 경로는 선형 Lerp다:

```
표시값 = (10.975 / 17.5)² = 39.3%
모델값 = 0.55 = 55%
```

**플레이어는 39.3%를 보면서 55%로 쏘고 있다.** 두 매핑이 한 화면에 있다.

## 5. 자기 벽은 45°에서 문제가 아니다 — 낮은 각도가 문제다

45°·충분한 속도에서는 자기 성벽(상단 3~5u)을 여유롭게 넘는다. 40.7%는 **낮은 각도** 구간이
대부분이다. 그러므로 이 결함의 형태는 "각도를 낮추면 자기 벽, 파워를 낮추면 미달,
파워를 높이면 지나침" 사이의 **좁은 띠**다.

## 6. 부수 발견 — 레인 주석이 실제 표와 다르다

`DynamicBattlefield.cs:310` 주석: *"Inner lane indices in SpawnLanes: {-6.5, 0, 6.5}"*
실제 표(`:219`): `{−13.5, −11.0, −2.5, 0, 2.5, 11.0, 13.5}`, 내부 인덱스(`:314`) `{2,3,4}`
→ **`{−2.5, 0, +2.5}`**. 주석의 ±6.5는 표에 없는 값이고, 같은 주석이 "±6.5 레인은 케그가
점유한다"고도 적는다. 표가 바뀌고 주석이 남았거나 그 반대이며 **어느 쪽인지 확인하지 않았다.**

---

## 이 계산이 말하지 않는 것

- **바람 없음.** 프리뷰는 위치 종속 바람을 반영하는데(`LaunchManager.cs:973-978`) 이
  재현은 무풍이다. 띠가 이동한다 — 방향은 계산하지 않았다.
- **붕괴 연쇄 없음.** 자기 벽 상단이 무너지면 통과 가능해지므로 40.7%는 **경기 시작
  시점**의 값이다. 감소량 미측정.
- **장애물이 이동한다.** Patrol은 `MovingGimmick`이고 구성은 3턴마다 변한다. 13.0%는 한
  배치의 스냅샷이다.
- **콜라이더 크기 미반영.** 발사체는 점이 아니라 박스캐스트이므로(`:991-999`) 실제 도달은
  이 계산보다 넓을 수 있다. PM 레인이 순수 탄도 기준 20.0%를 냈고 이 계산이 6.3%인 차이의
  일부가 그것이다 — **6.3%는 비관 끝, 20.0%는 낙관 끝으로 읽어야 한다.**
- **6.3%가 결함이라고 판정하지 않는다.** 디자이너 레인 판정이며 이 문서는 숫자만 낸다.
  다만 **기본값이 자기 벽에 떨어지는 것은 숫자만으로 결함이다.**
