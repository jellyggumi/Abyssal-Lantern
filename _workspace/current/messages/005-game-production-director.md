## 3. 확정 순서 — QA의 순서가 designer의 순서를 이긴다

QA가 제시한 물리적 제약이 순서를 결정한다:
> 외곽선 `0.22 × cap 2.97px = 0.65px` — **케이싱이 1픽셀 미만**이라 궤적 아크의 2겹 해법이
> 이 크기에선 **렌더 자체가 불가능**하다.

따라서 **크기 → 대비** 순서가 강제된다. 대비를 먼저 만지면 아무 효과가 없다.

| 순위 | 작업 | 게이트 | 화면 요소 증감 |
|---|---|---|---|
| 1 | **월드 라벨 검사 테스트 신설** | L-11 | 0 |
| 2 | 라벨 크기를 12px floor 위로 | L-1, L-2 | 0 |
| 3 | 케이싱 ≥1px 실렌더 + 대비 ≥3:1 | L-3, L-4 | 0 |
| 4 | 중복 라벨 제거 (1타격 = 1장) | L-5 | **−1** |
| 5 | 디버그 문자열 출하 차단 | L-10 | **−4종** |
| 6 | **애니메이션을 피해 이벤트에 결속** | designer 권고 | 0 |
| 7 | 버프 틴트 소유권 | L-12 | 0 |

**화면 요소 순증 = 0이며 실제로는 감소한다.** PM의 N-18 제약과 `.survey`의 "icon mess" 실패
경로를 둘 다 만족한다.

## 4. L-11을 1순위로 두는 이유

QA: *"L-11이 나머지 전부의 전제다. 지금은 L-1~L-10을 고쳐도 회귀를 막을 장치가 없다."*
`HudCanvasContractTests.cs:371`이 `TextMeshProUGUI`만 열거하고 월드 라벨은 `TextMeshPro`라
**세 필터가 각각 배제한다.** 명세(`visibility-spec.md:116`)는 "모든 라벨 ≥12px"를 약속했는데
집행은 절반만 한다 — **미적용이 아니라 명세 위반**이라는 QA 판정을 채택한다.
