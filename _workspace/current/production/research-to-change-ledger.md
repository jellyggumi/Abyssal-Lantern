## 1. 조사가 인게임을 안 바꾼 이유

조사는 답을 찾았다. **답이 이미 코드에 있고 꺼져 있었다.**

```
BrickPlacementController.cs:95
  "Designation window: the OPPONENT's turn only"
  → 적 턴에 클릭해 벽돌 예약, 내 턴에 실체화 (장치 D3)

BrickPlacementController.cs:76-82
  → EnforcesOneShotTurns일 때 조기 반환
GameManager.cs:144
  → enforceOneShotTurns = true 가 기본값
```

D3은 비교작 10개 중 **1개(XCOM 2)** 에만 있어 G8 참신성 임계값도 통과한다.
플래그 하나로 켤 수 있어 보였다.

### 그런데 세 레인이 독립적으로 블로커를 하나씩 찾았다

| 블로커 | 깨지는 게이트 | 실측 | 찾은 레인 |
|---|---|---|---|
| AI 미러 부재 | G2 승률 | `SimpleAI` 238줄에 벽돌 0줄 | design → eng 확인 |
| 자재 순증 | G7 페이싱 | 판당 3,641 HP vs 예산 42.9 = **84.8배** | eng |
| 패널 화면 밖 | G4 몰입 | 버튼 가시 **19.4%** | QA → eng 확인 |

그리고 PM이 넷째를 찾았다:

> **그대로 켜면 적 턴에 손 안 대는 플레이어가 51%p 진다.** 밴드(≤10%p)의 5.1배.
> AI 미러를 붙여도 49%p로 **오히려 악화**한다 — 밸런스 모델만 구제되고
> 무행동 플레이어는 0%가 된다.

### 결정적 이유: 측정이 불가능한 상태였다

디자이너가 부수적으로 찾은 것이 순서를 뒤집었다.

> **G2 승률이 기믹 이전에 이미 87%다.** 밴드 45~55%의 32pp 밖.
> 원인은 기믹이 아니라 선공 고정(`GameManager.cs:1678`)이고,
> `qa/evidence/g2-winrate-measurement.txt`가 해법도 적어뒀다 — 교대 시 49.0% INSIDE.

이번 사이클의 운영 모드가 **"측정 인프라"** 인데 측정 대상이 눈금 밖에 있었다.
87%인 판에 기믹을 넣으면 좋아졌는지 나빠졌는지 읽을 수 없다.

**그래서 순서를 뒤집었다: 선공 교대 → 재측정 → 기믹.**

## 2. 조사가 실제로 바꾼 것 — 코드가 아니라 다음 행동

코드가 안 바뀌었다고 아무것도 안 바뀐 건 아니다.

| 조사 전 (가정) | 조사 후 (실측) |
|---|---|
| "턴제라서 심심하다" | **반증** — 턴제 7종 중 6종이 랠리 장치 보유 |
| "기믹을 추가해야 한다" | **답이 이미 코드에 있고 꺼져 있다** |
| "켜면 된다" | 블로커 3개 + 공정성 51%p |
| "기믹으로 재미를 잰다" | **G2가 이미 32pp 밖이라 못 잰다** |
| 다음 작업 = 기믹 구현 | 다음 작업 = **선공 교대** |

### 진단: 우리는 랠리 게임이 아니다

| | 피카츄 배구 | castle-war |
|---|---|---|
| 주도권 객체 | **공 하나 공유** | 각자 생성·소멸 (독립 시뮬 2개) |
| 한 교환 간격 | 1.12초 | **7.5초** (6.7배) |
| 상대 턴 중 내 입력 | 25Hz | **0** (코드 경로 3개가 차단) |
| 유휴 비율 | 8% | **62.2%** |

유휴는 항등식 `1 − D/15`라 **경기 길이·벽 두께·턴 수와 무관**하다 —
밸런스 튜닝으로는 절대 안 움직인다. D(플레이어 결정 소요)만이 움직인다.

## 3. 인게임에 실제로 들어간 것 — 출처별

### (A) 사용자 버그 신고 → HUD 수정 (내 커밋 `0cb0efb9`)

**"버전업 후 글씨가 깨진다"** — `KEEP CORE`가 `KLLP CORL`로 찍혔다.

| # | 플레이어가 보는 변화 | 코드 |
|---|---|---|
| 1 | **글자가 안 깨진다** | `HudCanvas.Resolve()` — 순회 순서 대신 이름으로 캔버스 확정 |
| 2 | **작은 창에서도 읽힌다** | `HudScaleFloor` — 1024×576 아래로 안 줄어듦 |
| 3 | **글자가 커졌다** | 17/15/14pt → 26/23pt 상수화 |
| 4 | **바람·점수가 처음으로 보인다** | `windText`·`scoreText` 입양 (캔버스 조상이 없어 한 번도 안 그려짐) |
| 5 | **좌상단이 안 겹친다** | 바람 2줄→1줄, 보급 줄바꿈 금지, 토글 간격 |
| 6 | **코어 배지가 자기 성 위에 있다** | 0.18/0.82 → 0.325/0.675 |
| 7 | **턴 토스트가 타이머를 안 가린다** | 0.78 → 0.76 |

> **정정 (2026-08-13).** 이 문서 초안은 "순회 순서 호출 0건"이라 적었고 **틀렸다.**
> 검산에서 1건이 잡혔다 — 병합이 동시 세션의 새 호출부(`SelectedUnitPortrait`,
> `LaunchManager.cs:300`)를 들여왔고 그것이 옛 패턴을 쓴다. 같은 결함이 다른 손으로
> 다시 들어온 것이다.
>
> 더 나쁜 것은 **내 회귀 테스트가 그걸 못 잡았다는 점**이다.
> `GameplayHudLabels_AllShareTheOneHudCanvas`가 `TextMeshProUGUI`만 셌고 새로 들어온
> 것은 `Image`였다. 규칙은 "모든 HUD 요소"인데 테스트는 "모든 라벨"만 검사하고 있었다 —
> 계약보다 좁은 테스트는 계약을 지키지 못한다. `Graphic` 전수로 넓혔고 호출부도 고쳤다.
> **재실행 검증은 사용자가 Unity를 쓰는 중이라 대기 중이다.**

창 크기별 실효 글자 크기:

| 창 | 이전 | 지금 |
|---|---|---|
| 1920×1080 | 17px | 26px |
| 1024×576 | 9.1px | **13.9px** |
| 640×480 | **6.5px** ← 깨짐 | 13.9px (클램프) |

> 원인은 폰트가 아니었다. 6개 호출부가 `FindObjectOfType<Canvas>()`로
> **순회 순서에 의존**해, 코어 배지가 콜드오픈 영상의 `NarrativeCanvas`(scale 0.385)에
> 붙어 17pt가 6.5px로 렌더됐다. 그 크기에서 SDF 가로획은 한 픽셀 행을 못 채운다.
> 상세: `qa/hud-font-defect.md`

### (B) 동시 세션(`akillness`) → 조작·화면·안전

| 커밋 | 플레이어가 보는 변화 |
|---|---|
| `bec6a19f` | **어디서나 당겨 발사** (3.5u 링 안 누름 제한 제거) + 제스처 픽토그램 |
| `e9210477` | 하단 중앙 노란 크로스헤어 제거, 발사체 초상 표시 |
| `b40e29cf` | **첫 발사가 자기 코어를 깎던 결함** 수정 (화약통이 포구 스폰 영역에 있었음) |

`bec6a19f`는 **글리프 감사 게이트**(`FontGlyphAudit`)도 만들었다 — 아틀라스에
글리프가 없어 두부(`▸`)가 뜨는 것을 배치 전에 잡는다. **내 수정과 다른 결함이고
보완 관계다**: 그쪽은 *글리프가 있는가*, 내 쪽은 *읽을 크기로 그려지는가*.

### (C) 원래 범위 → 영웅 성장 시리즈 영속화 (`7ec1431f`)

전리품(검 +15% 피해 / 방패 +20% HP / 부츠 +12% 속도)이 **매 판 증발하던 것**을
시리즈(3판 2선승) 동안 유지되게 했다. 바꾼 것은 `HeroGrowth.Reset()` **호출 위치 하나**.

실측 캐리오버: 검 1스택 반입 시 Knight 피해 20.0 → **23.0**, 최대HP 100 → **120**.

## 4. 다음 사이클 착수 순서 (조사가 정한 것)

```
M1  선공 교대          → G2를 밴드 안으로 (측정 가능 상태 복구)
M2  u_wall 계측        → 목책 열 활용률 ≥84.4% 여부
M3  B3 패널 좌표       → 캔버스 결함 위에 얹혀 있으므로 HudCanvas 이후
C1  벽돌 예약 부활     → AI 미러 + 자재 보존 + 지연 차감
```

u_wall이 84.4% 미달이면 C1 대신 **C7(사전 조준)** 으로 분기한다.

M1은 "1줄"이 아니다 — `ExecuteAITurn()` 호출처가 `EndTurn():2150` 하나뿐이라
`:1678`만 바꾸면 AI 선공 경기가 15초 정지로 시작한다. 4~9줄 + 테스트 9건 조건화.
